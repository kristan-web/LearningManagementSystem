# Bug Scan Report

Generated by running the full automated test suite (`php artisan test`) plus a
manual static read-through of routes, middleware, and controllers most likely
to hide authorization/logic bugs. Tests run against an in-memory SQLite DB
(see `phpunit.xml`), so this was non-destructive to the real `enrollment_management_system` database.

**Result: 137 passed, 3 failed (411 assertions, ~11s).**

---

## 1. Real app bug: wrong HTTP status for unauthorized schedule PUT/DELETE

- **File:** `routes/web.php` (lines 61-62), `app/Http/Controllers/AdminScheduleController.php`
- **Symptom:** `tests/Feature/AdminScheduleTest::non_admin_role_is_forbidden_from_admin_schedule`
  expects `403 Forbidden` for a Teacher hitting
  `PUT /admin/schedule/1` and `DELETE /admin/schedule/1`, but gets `404 Not Found`.
- **Root cause:** Those two routes use implicit route-model binding
  (`Schedule $schedule` in the controller signature). Laravel resolves the
  model **before** the controller method body runs. When `schedule_id = 1`
  doesn't exist, Laravel throws `ModelNotFoundException` → `404`, before the
  `abort_unless(...)` role check ever executes. GET/POST on the same
  controller work correctly because they don't bind a model.
- **Why it matters:** inconsistent/leaky authorization — a non-admin can
  distinguish "record exists" (403) from "record doesn't exist" (404) on
  routes that should uniformly deny them, and the behavior is inconsistent
  with sibling controllers.
- **How the rest of the codebase avoids this:** `SubjectController` and
  `EnrollmentController` take a raw `$id` (not a type-hinted model) and call
  `Model::findOrFail($id)` manually, *after* the `abort_unless` role check.
  There's also a purpose-built `EnsureAdmin` middleware
  (`app/Http/Middleware/EnsureAdmin.php`, aliased as `role` in
  `bootstrap/app.php`) whose doc comment literally says it exists to "block
  non-admin users... before route-model binding resolves (so they get 403,
  not 404)" — but `AdminScheduleController`'s routes never apply it.
- **Suggested fix (root cause, one place):** change `update()`/`destroy()` in
  `AdminScheduleController` to accept `$schedule_id` and call
  `Schedule::findOrFail($schedule_id)` after the `abort_unless` check (same
  pattern as `SubjectController`), **or** apply the existing `role:admin`
  middleware to the `/admin/schedule/*` route group so the check runs before
  binding. Either fixes all three verbs identically — no need to special-case
  PUT vs DELETE.

## 2. Real app bug: unreachable dead code + wrong request type in `CalendarController::events()`

- **File:** `app/Http/Controllers/CalendarController.php`, lines 62-72 (inside `events()`)
- **Symptom:** not covered by a failing test, found via static read-through.
- **Root cause:** `events()` already returns early for `role === 'Admin'` at
  line 51. The block at lines 62-72 re-checks `role === 'Admin'` — a branch
  that can never be reached — and appears to be copy-pasted from `store()`.
  It also calls `$request->validated()`, but `events()`'s parameter is a plain
  `Illuminate\Http\Request`, not a `FormRequest` with validation rules, so
  calling `validated()` on it would throw a `LogicException` if this dead
  code were ever somehow reached.
- **Suggested fix:** delete lines 61-72 (the stray `$student = ...` lookup
  plus the dead `if (Admin)` block) — `events()` should just fall through
  from the Teacher check straight to
  `return response()->json($this->calendar->feedFor($student, $from, $to));`
  with `$student` resolved right before that line, as it was likely intended.

## 3. Test bugs (not app bugs) — two schedule-conflict tests reuse one section

- **File:** `tests/Feature/AdminScheduleTest.php`
- **Failing tests:**
  - `admin_cannot_create_schedule_with_room_conflict` (line ~162)
  - `admin_cannot_update_schedule_with_teacher_conflict` (line ~221)
- **Root cause:** `AdminScheduleController::detectConflict()` checks for
  conflicts in this order: **section → teacher → room**. Both tests build two
  schedules that share the *same* `ClassSection`, so the section-conflict
  check fires first and returns `"Section is already scheduled..."`, while
  the test asserts the message contains `"Room is already booked"` /
  `"Teacher is already scheduled"` — testing a code path that was already
  short-circuited by the section conflict one line earlier in the controller.
  **This is a test-data bug, not a controller bug** — the controller's
  conflict detection is working as designed; the tests just don't isolate
  the condition they intend to exercise.
- **Suggested fix:** in both tests, create two separate sections (e.g. using
  the existing `makeSection()` helper twice) so the section check doesn't
  trigger before the room/teacher check the test is actually targeting.

## 4. Minor / non-blocking

- `tests/Feature/AdminScheduleTest.php` methods use the deprecated
  `/** @test */` doc-comment convention. PHPUnit 12 emits a deprecation
  warning for every one of them ("Metadata in doc-comments is deprecated...
  Update your test code to use attributes instead") and support will be
  removed in a future PHPUnit version. Recommend migrating to the
  `#[Test]` attribute when these tests are next touched.
- `php -l` syntax lint across every file in `app/` — **clean, no syntax
  errors**.
- `.env` is correctly excluded from git tracking (confirmed via
  `git log -- .env`, which shows a prior commit titled "Remove leaked secrets
  and stray files from tracking"). No secrets found currently committed.
